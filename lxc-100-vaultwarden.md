# LXC 100: Vaultwarden

Unprivileged LXC container that runs [Vaultwarden](https://github.com/dani-garcia/vaultwarden) in Docker, plus the Arcane agent so the container can be managed centrally.

## 1. Container

Specification: 1 core, 512 MiB RAM, 8 GB on `local-lvm`.

`nesting=1` must be enabled on the container so Docker works inside the LXC. Install Docker from the official repository: https://docs.docker.com/engine/install/debian/

## 2. Vaultwarden

```bash
mkdir -p ~/docker/vaultwarden
nano ~/docker/vaultwarden/docker-compose.yml
```

```yaml
services:
  vaultwarden:
    image: vaultwarden/server:latest
    container_name: vaultwarden
    restart: always
    environment:
      - SIGNUPS_ALLOWED=true
    ports:
      - "8080:80"
    volumes:
      - vaultwarden-data:/data

volumes:
  vaultwarden-data:
    external: true
    name: vaultwarden_vaultwarden-data
```

The data volume is declared `external`, so it has to exist before the first start:

```bash
docker volume create vaultwarden_vaultwarden-data
```

> [!IMPORTANT]
> Vaultwarden speaks plain HTTP on port 8080 inside the LAN. Clients must use HTTPS through the Caddy reverse proxy ([LXC 101](lxc-101-caddy.md)), otherwise the Bitwarden clients refuse to work.

> [!WARNING]
> `SIGNUPS_ALLOWED=true` lets anyone who can reach the service create an account. Create your accounts, then set it to `false` and recreate the container.

## 3. Arcane agent

An Arcane agent runs in this LXC. Its compose file is generated by the Arcane manager in [LXC 102](lxc-102-apps.md) and is not modified.
