# Raspberry Pi

The Raspberry Pi 3 is the primary DNS/DHCP server of the network and hosts the Twingate Connector, UpSnap and an Arcane agent. It runs 24/7. Because it runs from an SD card, write operations are reduced (see [section 4](#4-sd-card-protection)).

## 1. Initial OS setup

Headless Debian-based OS, flashed with the official [Raspberry Pi Imager](https://www.raspberrypi.com/software/):

- OS: **Raspberry Pi OS Lite (64-bit)**
- Imager settings: hostname (e.g. `pihole`), default user, SSH enabled with **public-key authentication**

Because the Pi is itself the DHCP server, the **static IP must be set on the Pi** and not through the router. With NetworkManager (adjust the connection name, see `nmcli con show`):

```bash
sudo nmcli con mod "<CONNECTION>" ipv4.method manual \
  ipv4.addresses <pi-IP>/24 ipv4.gateway <gateway-IP> ipv4.dns 127.0.0.1
sudo nmcli con up "<CONNECTION>"
```

## 2. Core services

The core network services run directly on the OS (not in Docker), so name resolution works even if Docker fails.

- **Pi-hole (v6):** [one-step installer](https://github.com/pi-hole/pi-hole/#one-step-automated-install)
- **Unbound:** installed and configured exactly as in the official Pi-hole guide: https://docs.pi-hole.net/guides/dns/unbound/ (listens on `127.0.0.1:5335`, IPv6 disabled)

### 2.1 Pi-hole settings

| Setting (Pi-hole web UI) | Value |
| :--- | :--- |
| `Settings > DNS > Upstream DNS Servers` | only custom upstream `127.0.0.1#5335` (Unbound), all public resolvers unchecked |
| `Settings > DHCP` | DHCP server enabled, router `<gateway-IP>`, range `192.168.0.<START>` to `192.168.0.<END>` (outside the static IPs `outside the static addresses`) |

> [!IMPORTANT]
> Disable the DHCP server on the ISP router as soon as the Pi-hole DHCP server is active.

### 2.2 Local DNS records

Configured under `Settings > Local DNS Records`:

| Domain | IP address | Target service |
| :--- | :--- | :--- |
| `proxmox.lan` | `<proxmox-IP>` | Proxmox VE host |
| `pihole.lan` | `<pi-IP>` | Pi-hole web UI |
| `<DUCKDNS_DOMAIN>` | `<proxy-IP>` | Vaultwarden via Caddy (LXC 101) |
| `arcane.lan` | `<app-IP>` | Arcane web UI (LXC 102, port 3552) |
| `nas.lan` | `<nas-IP>` | Samba NAS (LXC 103) |

> [!NOTE]
> Vaultwarden clients require a trusted HTTPS certificate. A `.lan` name can not get one, so the Vaultwarden record uses a DuckDNS domain. Caddy obtains the certificate via DNS challenge, see [LXC 101](lxc-101-caddy.md). Pi-hole resolves this domain to the internal Caddy IP.

## 3. Docker

Docker runs the Twingate Connector, UpSnap and the Arcane agent. Install it from the official repository: https://docs.docker.com/engine/install/debian/ (including the post-install step to run docker without `sudo`).

### 3.1 Docker Compose

> [!NOTE]
> The compose files of the Twingate Connector and the Arcane agent are generated by their providers. They are documented here for completeness.
```bash
mkdir -p ~/docker/twingate-upsnap
nano ~/docker/twingate-upsnap/docker-compose.yml
```

```yaml
services:
  twingate-connector:
    container_name: twingate-connector
    restart: unless-stopped
    image: twingate/connector:latest
    environment:
      - TWINGATE_NETWORK=<TWINGATE_NETWORK>
      - TWINGATE_ACCESS_TOKEN=<ACCESS_TOKEN>
      - TWINGATE_REFRESH_TOKEN=<REFRESH_TOKEN>
      - <TIMEZONE>

  upsnap:
    container_name: upsnap
    image: ghcr.io/seriousm4x/upsnap:latest
    network_mode: host # required to send Wake-on-LAN packets reliably
    restart: unless-stopped
    environment:
      - <TIMEZONE>
    volumes:
      - ./data:/app/pb_data
```

In UpSnap, add the Proxmox host as device (MAC address of the NIC, IP `<proxmox-IP>`). UpSnap wakes it via Wake-on-LAN.

```bash
docker compose up -d
```

The **Arcane agent** is generated by the Arcane manager in LXC 102 (see [LXC 102](lxc-102-apps.md)). Its compose file is stored as `~/docker/arcane-agent/docker-compose.yml`.

```bash
mkdir -p ~/docker/arcane-agent
nano ~/docker/arcane-agent/docker-compose.yml
```
```yml
services:
  arcane-agent:
    image: ghcr.io/getarcaneapp/agent:latest
    container_name: arcane-agent
    restart: unless-stopped
    environment:
      - AGENT_MODE=true
      - AGENT_TOKEN=<YOUR_AGENT_TOKEN>
      - MANAGER_API_URL=<app-IP>
    ports:
      - "3553:3553"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - arcane-data:/app/data

volumes:
  arcane-data:
```
```bash
docker compose up -d
```

## 4. SD card protection

### 4.1 Log2Ram

Keeps `/var/log` in RAM and writes it to the SD card only periodically. Installation: https://github.com/azlux/log2ram

```bash
sudo nano /etc/log2ram.conf
```

```
SIZE=128M
USE_RSYNC=true
```

`USE_RSYNC=true` only writes changed files back to the SD card. Adjust `SIZE` to the available RAM (the Pi 3 has 1 GB).

### 4.2 Docker logs to journald

By default Docker writes JSON logs to the SD card. They are redirected to journald, whose size is limited:

```bash
sudo nano /etc/docker/daemon.json
```

```json
{
  "log-driver": "journald"
}
```

```bash
sudo nano /etc/systemd/journald.conf     # set SystemMaxUse=50M
sudo systemctl restart systemd-journald docker
```

The new log driver only applies to newly created containers, so recreate the existing ones: `docker compose up -d --force-recreate`.

### 4.3 Pi-hole database interval

Pi-hole stores query data in a database. Increase the write interval to one hour. In Pi-hole v6 the value is configured in **seconds** in `/etc/pihole/pihole.toml`:

```bash
sudo pihole-FTL --config database.DBinterval 3600
```

Check with `sudo grep DBinterval /etc/pihole/pihole.toml`.

## 5. Backup of the Pi

The Pi is backed up by LXC 103. Two things are required on the Pi:

- The public SSH key (ed25519) of the root user in LXC 103 in `~/.ssh/authorized_keys` of `<PI_USER>`.
- Allow `rsync` without a password through sudo, because `/etc/pihole` and `/etc/unbound` are not readable by the normal user. Create the file with `sudo visudo -f /etc/sudoers.d/rsync-backup`:

```
Defaults!/usr/bin/rrsync env_keep += "SSH_ORIGINAL_COMMAND"
<PI_USER> ALL=(root) NOPASSWD: /usr/bin/rrsyncnc
```
The `Defaults` line is required: `sudo` resets the environment, and without `SSH_ORIGINAL_COMMAND` `rrsync` aborts with `Not invoked via sshd`

2. Prefix the public key in `~/.ssh/authorized_keys` of `<PI_USER>` with a forced command and restrictions:

```
restrict,from="<NAS-IP>",command="sudo /usr/bin/rrsync -ro /" ssh-ed25519 AAAA... root@nas
```

The key can then only read files through rsync, from one IP address, and can not open a shell or write anything. Test: `ssh <PI_USER>@<pi-IP> id` must no longer return a shell result.
